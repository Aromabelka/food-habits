# Food Habits

Простая русскоязычная анкета без регистрации: шесть демонстрационных вопросов, одиночный и множественный выбор, результат, рекомендации и необязательное разовое письмо.

## Локальная разработка

Нужен Node.js 20+. Сторонних npm-зависимостей нет.

```sh
npm run dev
# http://127.0.0.1:5173
npm run check
```

`npm run dev` собирает приложение при запуске; после изменения исходников выполните `npm run build` и обновите страницу. Вне Google Apps Script приложение явно работает в демо-режиме: результат считается локально, ответы не сохраняются и письма не отправляются. Можно открыть `dist/index.html` напрямую в современном браузере.

## Google Apps Script

Подготовленный проект: https://script.google.com/d/1GOPEywmWh7qF3DRgQe0nC8E8nRhJRbmyElfIsSSU4XNsfF7UZ2iqUdma/edit

База данных: https://docs.google.com/spreadsheets/d/18UyMYLDH8G07v3bw1kXqEsq-uOS3tBursErZpWcYyx8/edit

1. Откройте проект Apps Script под аккаунтом с правом редактирования указанной таблицы.
2. В редакторе выберите функцию `setup_` из `Code.gs` и нажмите Run / Выполнить. Подтвердите запрошенные Google разрешения на таблицы и отправку почты. Функция создаёт листы `Questions`, `Results`, `Responses` и секрет подписи. Существующие заполненные листы и `Лист1` она не изменяет. Её нельзя вызвать из браузера через `google.script.run`.
3. Deploy → New deployment → Web app. Execute as: **Me**, Who has access: **Anyone** (не «Anyone with Google account»). Откройте полученный URL `/exec` в приватном окне: посетителю не нужна авторизация. Возможность анонимной публикации зависит от политики вашего Google Workspace.
4. Пройдите анкету и убедитесь, что в `Responses` появилась одна строка. Для проверки письма используйте собственный email и согласие. Реальные письма автоматическими тестами не отправляются.

Код можно загрузить вручную из `dist/apps-script`: `Code.gs`, `Survey.gs`, `Index.html`, `appsscript.json`. Чтобы увидеть manifest в редакторе, включите его отображение в настройках проекта.

Для обновлений через установленный `clasp`:

```sh
npm run check
clasp push --force
clasp deploy --description 'Food Habits update' --deploymentId YOUR_DEPLOYMENT_ID
```

Локальная `.clasp.json` привязана к созданному проекту, не коммитится. Для другой машины скопируйте `.clasp.example.json` в `.clasp.json` и выполните `clasp login`. `dist` пересобирается и также не коммитится.

## Как менять содержание

Порядок строк в `Questions` задаёт порядок вопросов. Колонки:

| Колонка | Значение |
| --- | --- |
| id | Уникальный стабильный идентификатор |
| title | Текст вопроса |
| hint | Подсказка |
| multiple | TRUE — несколько ответов, FALSE — один |
| options_json | JSON-массив вариантов |

Пример `options_json`:

```json
[{"id":"yes","label":"Обычно да","score":2},{"id":"sometimes","label":"Иногда","score":1},{"id":"no","label":"Пока нет","score":0,"exclusive":true}]
```

`exclusive` запрещает сочетать вариант с другими. Вопросы обязательные. За вопрос начисляется среднее значение `score` выбранных вариантов (0–2); затем среднее по вопросам переводится в 0–100 и округляется. Чем больше вариантов отмечено, тем выше результат автоматически не становится.

`Results` содержит `id`, `min`, `max`, `title`, `description`, `recommendations_json`. Рекомендации — JSON-массив строк. Диапазоны целочисленные, включают границы и должны покрывать 0–100 без пересечений. Демо: 0–39, 40–74, 75–100. Это условная группировка для самоанализа, не валидированная шкала здоровья. Числовой балл не показывается посетителю.

Изменения вопросов/результатов в таблице не требуют перепубликации. Если содержание изменилось во время заполнения, сервер предложит обновить страницу. Сохранённый результат и письмо используют один и тот же снимок рекомендаций.

## Архитектура и данные

- `src/` — интерфейс на HTML/CSS/JavaScript, демонстрационный контент и общая логика проверки/расчёта.
- `apps-script/Code.gs` — HtmlService, чтение Sheets, проверка ответов, запись результата, отправка через MailApp.
- `scripts/build.mjs` — собирает единый HTML и проект Apps Script без внешнего сборщика.
- `tests/` — тесты расчёта и серверной логики с подменой Google API.
- Продакшен-интерфейс обращается к серверу через `google.script.run`; отдельный сервер и CORS-прокси не нужны.
- Ответы сохраняются после последнего вопроса независимо от email. До отправки они находятся только в памяти страницы; обновление страницы начинает анкету заново.
- Email сохраняется только при запросе письма с явным согласием, вместе с временем согласия и статусом отправки. Публичного API чтения ответов нет. Таблица должна оставаться закрытой для посетителей.
- UUID делает повторную отправку одинаковых ответов идемпотентной. Секрет HMAC находится в Script Properties; клиент получает токен доступа только к своему результату.
- Лимит: одно письмо на результат, один запрос на email за 24 часа, до 50 попыток за скользящие 24 часа и в рамках квоты MailApp. Срок запроса письма — 24 часа после анкеты.
- `pending` фиксируется до вызова MailApp. Если сервис вернул неопределённый сбой, приложение не отправляет письмо повторно автоматически. `sent` означает успешный ответ MailApp, а не гарантированную доставку в почтовый ящик.
- Для публичной рекламной кампании потребуется отдельная защита от ботов: текущие ограничения уменьшают повторную отправку, но не предотвращают массовые анонимные submissions. Это небольшое MVP на квотах Apps Script.
- Срок хранения и удаление записей определяет владелец таблицы. Автоматического удаления нет.

## Проверка

`npm run check` запускает 11 тестов и сборку. Покрыты диапазоны результата, ошибки ввода, множественный/исключающий выбор, версия анкеты, повторные submissions, согласие, токены, повторы email, лимиты и неопределённый сбой отправки. Тесты Google API изолированы; доступы, реальную запись в Sheets и доставку писем нужно проверить после первого запуска `setup_` и публикации.

Официальные справочники: [Web Apps](https://developers.google.com/apps-script/guides/web), [google.script.run](https://developers.google.com/apps-script/guides/html/communication), [MailApp](https://developers.google.com/apps-script/reference/mail/mail-app).

## GitHub Pages

Workflow `.github/workflows/pages.yml` запускает тесты, собирает приложение и публикует только `dist/index.html`. Серверный код Apps Script и его manifest не попадают в публичный артефакт.

Владелец репозитория должен один раз выбрать **Settings → Pages → Build and deployment → Source: GitHub Actions**. После этого публикация запускается при каждом push в `main` или вручную через **Actions → Deploy GitHub Pages → Run workflow**. Для приватного репозитория нужен тариф GitHub с поддержкой Pages.

На GitHub Pages работает демоверсия без записи ответов и отправки писем. Полная версия с Sheets и MailApp размещается через Apps Script по инструкции выше.
