# Анкета пищевых привычек Елены Вилиткевич

Версия анкеты и маршрутизации **2.1**: спецификация 2.0 с согласованными изменениями. Шпаргалок и выдачи рекомендаций по email нет. После результата предлагается добровольная подписка на письма Елены.

Сайт: https://aromabelka.github.io/food-habits/

## Запуск и проверка

Node.js 20+, без npm-зависимостей:

```sh
npm run dev
npm run check
```

Предпросмотр: http://127.0.0.1:5173. Сборка выполняется при запуске; после изменений выполните `npm run build` и обновите страницу. Локальное прохождение анкеты работает полностью. Межсайтовый канал подписки разрешён только для `https://aromabelka.github.io`; локальная форма намеренно не отправляет данные.

13 тестов проверяют ветвление, неизвестные ответы, приоритеты, валидацию контактов, согласие, защиту от повторов, подтверждение, отписку и сбои почты. Один тест перебирает все 32 768 корректных сочетаний ответов.

## Правила

- 7 вопросов, плюс уточнение первого приёма пищи для тех, кто обычно не завтракает.
- Один ответ на вопрос. При выходе из ветки скрытый ответ очищается.
- P: балл за регулярность белка в завтраке / первом приёме пищи.
- V: максимум известных баллов за овощи, фрукты и разнообразие. Одного известного ответа достаточно. Если все неизвестны — null.
- W: неизвестное количество напитков → null; высокий диапазон → 0. Остальные случаи → 1, кроме сочетания малого количества с частым забыванием или откладыванием → 2.
- Максимум, при равенстве P → V → W. Растительное наблюдение при равенстве: разнообразие → овощи → фрукты, с одним соответствующим действием.
- Нет положительных баллов: поддержка белковой привычки, если P=0; иначе ориентирование без утверждения о недостатке.
- Баллы не показываются посетителю. Шкала не является диагностической.

Первый запуск должен выполнить владелец Google-проекта:

1. В редакторе выбрать `setup_`, нажать «Выполнить», предоставить доступ к Google Sheets и отправке писем.
2. Deploy → Manage deployments: Web app, Execute as **Me**, Who has access **Anyone**. Аккаунт исполнителя должен иметь право редактирования указанной таблицы.

### Таблицы

`setup_` добавляет листы `Subscribers` и `QuestionsV2`, не перезаписывает старые листы демоверсии.

`QuestionsV2`: id, title, hint, options_json. Редактируются формулировки и подписи вариантов. Коды, ветвление и баллы задаются версионированным исходником `src/survey.js` и не меняются от правки текста. Клиент получает вопросы через Apps Script, при недоступности используются встроенные формулировки. Ответ, начатый до загрузки удалённых формулировок, остаётся на текущей версии текста.

`Subscribers`: request_id, requested_at, name, email, marketing_status, consent_text_version, consent_text, confirmed_at, unsubscribed_at, mail_status, answers_json, result_json.

Ответы без заявки на подписку не отправляются в базу. При заявке сервер сам проверяет ответы и рассчитывает результат. Имя и email сохраняются вместе с согласием независимо от успеха отправки письма. Начальное состояние — `pending`, затем `confirmed` или `unsubscribed`. При подготовке любой рассылки использовать только подтверждённые адреса, исключать отписавшихся, удалять дубликаты. Сервис массовой рассылки не реализован.

### Подписка и письма

Имя: 1–80 символов после trim. Email: trim, домен в нижнем регистре, точки и plus-суффиксы сохраняются. Опасные для Google Sheets начальные символы экранируются. Согласие обязательно только для подписки.

Подтверждение и отписка используют подписанные HMAC-ссылки. GET показывает кнопку; изменение статуса происходит по POST, поэтому обычное сканирование ссылки почтовым сервисом не подписывает человека. Подтверждение действительно 7 дней. Отписка отменяет все текущие записи этого email. Новая заявка после отписки требует нового подтверждения.

Повторный request_id не создаёт вторую строку/письмо. До отправки фиксируется `unknown`, после ответа MailApp — `sent`. При неопределённом сбое автоматической повторной отправки нет. До 50 попыток отправки в сутки, не более одного подтверждения одному адресу за 24 часа. Повторная заявка с новым ID может быть сохранена без письма; это явно сообщается на экране. Для MVP нет защиты от массовых заявок ботов; перед рекламной кампанией нужна дополнительная защита.

Фактический адрес отправителя — аккаунт владельца Apps Script, отображаемое имя — Елена Вилиткевич. Перед запуском убедиться, что Елена имеет доступ к ответам на этот ящик. Массовая рассылка должна добавлять ссылку отписки для соответствующей записи; в письме подтверждения такая ссылка уже есть.

### Связь с GitHub Pages

Скрытый iframe открывает Apps Script Bridge. Передача данных — postMessage с точной проверкой origin, случайного channel и окна-отправителя, затем `google.script.run`. Ответы и контакты не включаются в URL. В URL bridge есть только случайный технический канал. Клиент не объявляет сохранение успешным до ответа сервера.

## Политика конфиденциальности

`src/privacy.html` — текст под фактический сценарий; ссылка есть у формы. Внешние шрифты/аналитика не подключены. Для обращений используется ответ на письмо подтверждения. Перед запуском владельцу нужно подтвердить рабочий контакт, условия Google/GitHub и порядок хранения. Автоматическое удаление не реализовано; политика прямо это указывает. Это проектный текст, а не юридическое заключение.

## Публикация

Push в `main` запускает тесты и публикацию GitHub Pages. В публичный артефакт попадают только `index.html` и `privacy.html`; таблица, контакты и учётные данные туда не входят. Apps Script обновляется отдельно указанной командой.
